# Phone app (LIVE from a phone)

An installable phone app that shows the desktop app's game screen full screen (no browser bar), so the streamer can go LIVE with the TikTok app's **screen share**. The computer still runs the games, the TikTok connection and the overlay; the phone only displays.

It needs the desktop's **phone screen** server (panel **📱 LIVE bằng điện thoại**, `/phone` page on port 17322, see `docs/OVERLAY.md`). Until that feature is on this branch, the app builds and pairs but has nothing to connect to.

Two versions of the same app, to compare:

| | Capacitor | Expo (React Native) |
|---|---|---|
| Code | `src/mobile/*` (React DOM + CSS), `mobile/index.html` | `mobile-expo/` (own `package.json`) |
| Game screen | `<iframe sandbox>` of the /phone page | `react-native-webview` |
| Native projects | `mobile/android`, `mobile/ios` (committed) | generated by `expo prebuild` / `expo run` (gitignored) |
| App id | `local.tiklivevpn.screen` | `local.tiklivevpn.screenexpo` (both can be installed side by side) |
| Try it | build and install (below) | `npx expo start` + **Expo Go** app |

Both share `src/shared/phoneLink.ts` (pairing link check, tested in `tests/phoneLink.test.ts`) and the i18n dictionary (`src/shared/en/mobile.ts`).

## Using the app

1. Phone and computer on the same Wi-Fi. On the computer: **📱 LIVE bằng điện thoại → Bật màn hình điện thoại**.
2. In the app: **📷 Quét mã QR** (or paste the link). The link is saved; next time the app opens straight on the game screen.
3. Tap **▶ Chạm để bắt đầu** on the game screen (starts the game sound), then start the screen-share LIVE in the TikTok app.
4. Menu: hold the top-left corner ~1 s (or Android **Back**): **🔄 Tải lại**, **Đổi máy tính**, **Đóng**.

While the game shows: status / navigation bars are hidden and the screen stays on. If the computer can't be reached, the app says so and retries every 3 s.

## Build: Capacitor

Node ≥ 22 (the Capacitor CLI requires it).

```bash
npm run mobile:build      # vite build → dist-mobile, then cap sync
npm run mobile:apk        # Android debug APK → mobile/android/app/build/outputs/apk/debug/app-debug.apk
npm run mobile:android    # open in Android Studio
npm run mobile:ios        # open in Xcode (pick your Team under Signing, then Run on the iPhone)
npm run mobile:dev        # pairing screen in a desktop browser (no native features)
```

- Android: `minSdkVersion` 26 (Android 8.0+, required by the barcode scanner). Gradle needs JDK 21 (Android Studio's bundled JBR works: `JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"`).
- `MainActivity.java` hides the system bars (immersive); `AndroidManifest.xml` allows cleartext HTTP (the LAN page) and the camera.
- iOS `Info.plist`: `NSAllowsLocalNetworking` (HTTP to LAN addresses only), local-network and camera usage texts, status bar hidden.
- The app page is `http://localhost` on Android (`androidScheme: 'http'`) so the plain-HTTP LAN page can load in its frame.

## Build: Expo

```bash
cd mobile-expo
npm install
npx expo start            # scan the QR with Expo Go (Android) / the Camera app (iPhone)
npx expo run:android      # local native build (Android Studio SDK)
npx expo run:ios          # local native build (Xcode)
```

`app.json` sets the app id, cleartext HTTP (`expo-build-properties`), `NSAllowsLocalNetworking`, the local-network and camera texts. `metro.config.js` lets Metro bundle `../src/shared`.

## Security

- Only links that pass `parsePhoneLink` are loaded: `http://` + a private IPv4 (10/8, 172.16/12, 192.168/16) + port 17322 + `/phone` + a 22–64 character token. Stored links are re-checked on load.
- Capacitor: the page runs in an `<iframe sandbox="allow-scripts allow-same-origin">` on the computer's origin, so it can't reach the app's plugins or navigate the app; the app's CSP allows frames / requests only to port 17322.
- Expo: the WebView may only navigate to the paired page, opens no windows, has no file access and no message bridge.
- The phone page itself is read-only (it sends nothing back to the computer).
